# P003-T001 — Add "one operation per round" to SPEC §18.6 and SKILL.md

**Status:** Verified
**Owner:** Implementer
**Plan:** P003

## Objective

Add the normative rule that each RaC round performs exactly one operation, and enforce it in `SKILL.md`. For example, `Verify` records verification evidence and `Close` updates the review status in a separate round; the two MUST NOT be performed in one shot.

**Depends on:**

- None

- [x] §18.6 states that each round MUST perform exactly one operation.
- [x] §18.6 states that `Verify` and `Close` MUST be performed in separate rounds, never in one shot.
- [x] §18.6 states that updating the derived `State` is part of an operation, not a separate operation.
- [x] `SKILL.md` Operations section enforces one operation per round.
- [x] §18.6 uses normative language consistent with `SPEC.md` §2.

## Implementation

Added normative `### 18.6 One operation per round` to `SPEC.md` after §18.5, stating each round MUST perform exactly one operation, that `Verify` and `Close` MUST be performed in separate rounds and never in one shot, and that updating the derived `State` is part of an operation rather than a separate operation. The section uses RFC 2119 normative language consistent with `SPEC.md` §2. Enforced the rule in `SKILL.md` under `## Operations` with a reference to `SPEC.md` §18.6 and the `Verify`/`Close` example.
