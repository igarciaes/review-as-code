# F001 — SPEC §7.1 finding example uses prose form inconsistent with status projections

Status: open

Severity: low

Location:
SPEC.md, Section 7.1

## Observation

The finding example in §7.1 shows `## Decision` and `## Verification` sections containing bare prose (`Pending.`) with no `Status:` subfield:

```markdown
## Decision

Pending.

## Verification

Pending.
```

Every other artifact in the changeset uses the `Status: <value>` form: §13 append-oriented examples (`Status: accepted`, `Status: verified`), the §15.1 Markdown-to-schema projection, all `examples/*/findings/*.md`, and `schemas/finding.schema.json`. A literal §15.1 projection of the §7.1 example yields `decision: "Pending."` and `verification: "Pending."`, which fail the schema's decision and verification enums.

## Recommendation

Align the §7.1 example with the `Status: <value>` form used everywhere else:

```markdown
## Decision

Status: pending

## Verification

Status: pending
```
