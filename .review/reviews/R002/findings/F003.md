# F003 — Schema wording contradicts enum enforcement

Status: open

Severity: low

Location:
schemas/finding.schema.json, decision and verification properties

## Observation

The `decision` and `verification` schema properties each carry the description "Recommended values from SPEC Section 8.x. Repositories MAY use other values." while simultaneously declaring a closed `enum`. Under JSON Schema, an `enum` rejects any value outside the listed set, so the "MAY use other values" wording is unenforceable and misleading: a repository that actually uses a custom value would fail validation despite being told it may.

## Recommendation

Resolve the contradiction by either:

- removing the "Repositories MAY use other values" wording so the description matches the enforced `enum`; or
- dropping the restrictive `enum` and presenting the vocabulary as non-normative guidance (for example in the `description` or in an `examples`/`$comment`), so custom values remain valid.
